EXECUTIVE SUMMARY
===============================================================================

MeTaCLIagenT is a META-ORCHESTRATOR framework for controlling and chaining
ANY command-line interface tool - whether AI coding assistants (Claude Code,
Codex, Gemini), traditional POSIX utilities (grep, sed, awk, git), or custom
applications that accept keyboard input.

CORE MISSION:
-------------
Build a robust, production-ready framework that:

1. Executes CLI tools SEQUENTIALLY and in PARALLEL
2. Saves every step, input, and output to a queryable database
3. Follows TEMPLATE-BASED RULES to automatically respond to outputs
4. Uses stdin/stdout where possible, PTY/expect patterns where needed
5. Simulates keyboard input for interactive applications
6. Provides full programmatic control over any text-based terminal application

DESIGN PHILOSOPHY:
-----------------
- UNIVERSAL: Works with ANY CLI tool (AI agents, POSIX utils, custom apps)
- ROBUST: Handles timeouts, errors, buffer overflow, edge cases
- PERSISTENT: Everything saved (SQLite DB + text files)
- INTELLIGENT: Template-based conditional responses
- FLEXIBLE: stdin/stdout, PTY, tmux, expect-style patterns
- SECURE: Sandboxed execution, audit logging, capability controls

2. USE CASE: PRACTICAL SCENARIOS
===============================================================================

2.1 AI Coding Tool Chain
-------------------------
SCENARIO: Generate code, review, fix, test

Sequence:
1. claude-code: "Write a REST API for user authentication"
   └─> Output: Python code with Flask

2. Template Match: IF code_generated THEN send_for_review
   └─> Next: gemini: "Review this code for security issues: {output}"

3. Template Match: IF security_issues_found THEN send_for_fix
   └─> Next: aider: "Fix these security issues: {issues}"

4. Template Match: IF code_fixed THEN run_tests
   └─> Next: pytest: "pytest tests/"

5. Template Match: IF tests_fail THEN debug
   └─> Next: claude-code: "Fix failing tests: {test_output}"

Database saves:
- Each tool invocation
- All inputs and outputs
- Timing and status
- Template matches
- Conditional branches taken

2.2 POSIX Tool Pipeline
-----------------------
SCENARIO: Log analysis and reporting

Sequence:
1. grep: Search logs for errors
   └─> grep -i "error" /var/log/app.log

2. Template: IF errors_found > 10 THEN extract_patterns
   └─> awk '{print $1, $4}' (extract timestamp and error type)

3. Template: IF critical_errors THEN alert
   └─> send-notification.sh

4. Parallel: Generate multiple reports
   ├─> python: analyze-errors.py
   ├─> R: plot-error-trends.R
   └─> pandoc: generate-report.md

All steps saved, queryable later

2.3 Mixed AI + POSIX Workflow
-----------------------------
SCENARIO: Codebase analysis and refactoring

Parallel Initial Analysis:
├─> claude-code: "Analyze architecture of src/"
├─> rg (ripgrep): Search for TODO comments
├─> git: Get commit history statistics
└─> cloc: Count lines of code

Sequential Follow-up:
1. Aggregate all analysis results
2. Template: Generate refactoring plan based on combined data
3. claude-code: "Create refactoring plan for: {analysis}"
4. Template: IF plan_approved THEN execute_refactoring
5. aider: Execute refactoring in stages
6. git: Commit each stage
7. pytest: Run tests after each stage

2.4 Interactive Application Control
-----------------------------------
SCENARIO: Automate interactive CLI tool that expects keyboard input

Tool: Custom interactive debugger or deployment tool

Expect-style rules:
- WAIT_FOR: "Continue? (y/n)"  → SEND: "y\n"
- WAIT_FOR: "Select option [1-3]:" → SEND: "2\n"
- WAIT_FOR: "Password:"  → SEND: "{password}\n"
- WAIT_FOR: "ERROR"  → ABORT and LOG

Uses PTY (pseudo-terminal) to fully emulate keyboard input
Saves all interactions to database for audit/replay

   - Pass output from step N to step N+1

   - Aggregate/synthesize results

C. Hybrid Execution (DAG)
   - Complex dependency graphs
   - Some steps parallel, some sequential
   - Conditional execution paths
   - Loop-back for retries

3.3 TEMPLATE & RESPONSE ENGINE
------------------------------

PURPOSE: Automatically generate follow-up commands based on output

TEMPLATE LANGUAGE:
-----------------

Rule Format:
IF <condition> THEN <action>

Conditions:
- output_contains("error")
- output_matches(regex_pattern)
- tool_exit_code == 0
- execution_time > 30.0
- step_number == 5
- variable == value

Actions:
- send_to_tool("claude-code", "Fix this error: {output}")
- run_parallel(["tool1", "tool2", "tool3"])
- abort_sequence()
- retry_with_backoff()
- save_checkpoint()
- branch_to_step(step_id)

Example Template:
----------------
```yaml
templates:
  - name: error_detected
    condition: output_contains("ERROR") or output_contains("Exception")
    action:
      type: sequential
      steps:
        - tool: claude-code
          prompt: "Debug this error: {output}"
        - wait: 2.0
        - tool: python
          prompt: "test_fix.py"

  - name: tests_failed
    condition: output_matches("(\d+) failed")
    action:
      type: conditional
      if: failed_count > 5
      then:
        - abort()
      else:
        - tool: aider
          prompt: "Fix the {failed_count} failing tests"

  - name: success_with_warnings
    condition: exit_code == 0 and output_contains("warning")
    action:
      type: parallel
      tools:
        - {tool: "claude-code", prompt: "Explain warnings: {warnings}"}
        - {tool: "grep", args: ["-A3", "warning", "{output_file}"]}
```

IMPLEMENTATION:
- Template parser (YAML/JSON)
- Condition evaluator
- Variable interpolation
- Context management
- Action executor

3.4 PERSISTENCE LAYER
----------------------

DUAL STORAGE STRATEGY:
---------------------

1. SQLite Database (Structured Queries)
   - sequences table: metadata, status, timing
   - steps table: individual step results
   - templates table: which templates matched
   - Full-text search (FTS5) on all outputs

   Schema:
   ```sql
   CREATE TABLE sequences (
       id TEXT PRIMARY KEY,
       name TEXT,
       type TEXT, -- 'sequential', 'parallel', 'hybrid'
       status TEXT, -- 'running', 'completed', 'failed', 'aborted'
       started_at TIMESTAMP,
       completed_at TIMESTAMP,
       total_steps INTEGER,
       successful_steps INTEGER,
       parent_sequence_id TEXT, -- for nested sequences
       template_used TEXT,
       context_data JSON
   );

   CREATE TABLE steps (
       id TEXT PRIMARY KEY,
       sequence_id TEXT,
       step_number INTEGER,
       tool_name TEXT,
       tool_args JSON,
       transport_type TEXT, -- 'pipe', 'pty', 'tmux'
       prompt TEXT,
       output TEXT,
       exit_code INTEGER,
       duration_seconds REAL,
       status TEXT,
       error_message TEXT,
       timestamp TIMESTAMP,
       template_matches JSON, -- which templates fired
       context_snapshot JSON
   );

   CREATE VIRTUAL TABLE outputs_fts USING fts5(
       step_id,
       output,
       content='steps',
       content_rowid='rowid'
   );
   ```

2. Text File Archives (Human-Readable)
   - One file per step
   - Grep-able, diff-able
   - Long-term archival

   Layout:
   ```
   logs/sequences/
   ├── 2025-11-27/
   │   ├── seq-001-codefix/
   │   │   ├── metadata.json
   │   │   ├── step-001-claude-code.txt
   │   │   ├── step-002-gemini.txt
   │   │   ├── step-003-aider.txt
   │   │   └── context.json
   ```

6.2 Example: Template-Based Code Fix
------------------------------------

Template: code_review.yaml
```yaml
name: code-review-fix
description: Generate, review, and fix code

steps:
  - id: generate
    tool: claude-code
    prompt: "Write a {language} function for: {task}"
    save_as: generated_code

  - id: review
    tool: gemini
    prompt: "Review this code for bugs:\n{generated_code}"
    templates:
      - condition: output_contains("security issue")
        action: branch_to(fix_security)

      - condition: output_contains("no issues")
        action: branch_to(done)

      - condition: output_contains("bug")
        action: branch_to(fix_bugs)

  - id: fix_bugs
    tool: aider
    prompt: "Fix these bugs: {output}"
    next: test_code

  - id: fix_security
    tool: aider
    prompt: "Fix security issues: {output}"
    next: test_code

  - id: test_code
    tool: pytest
    args: ["tests/"]
    templates:
      - condition: exit_code != 0
        action: retry_max(3, fix_bugs)

      - condition: exit_code == 0
        action: branch_to(done)

  - id: done
    action: save_result("final_code")
```

Usage:
```python
from eats_core import WorkflowTemplate

template = WorkflowTemplate.load("code_review.yaml")
result = template.execute(language="Python", task="binary search")
```

6.3 Example: Interactive Tool Automation
----------------------------------------

```python
from eats_core import CLISequence, ExpectRules

# Define expect rules for interactive deployment tool
rules = ExpectRules()
rules.add(pattern=r"Password:", response=lambda: os.getenv("DEPLOY_PASSWORD"))
rules.add(pattern=r"Continue\? \(y/n\)", response="y\n")
rules.add(pattern=r"Select environment \[1-3\]:", response="2\n")  # staging
rules.add(pattern=r"ERROR", action="abort")

# Create sequence
seq = CLISequence("deployment")
seq.add_step("./deploy.sh", expect_rules=rules, timeout=300.0)

# Execute - tool handles all prompts automatically
result = seq.run()

# Check result
if result.success:
    print("Deployed successfully!")
    print(f"Deployment log: {result.log_file}")
else:
    print(f"Failed: {result.error}")
    # All interactions saved to DB for debugging
```

7.3 Performance Characteristics
-------------------------------

Sequential Execution:
- Latency: Sum of all step latencies
- Throughput: Limited by slowest step
- Memory: One process at a time
- Best for: Dependencies between steps

Parallel Execution:
- Latency: Max of all step latencies
- Throughput: N x single step
- Memory: N processes simultaneously
- Best for: Independent operations

Expected Performance:
- PTY spawn: <100ms
- Pipe spawn: <10ms
- Buffer read: <1ms (non-blocking)
- DB write: <10ms per step
- Template match: <1ms

Benchmarks (target):
- 100 steps/minute (sequential)
- 1000 steps/minute (parallel, 10 workers)
- 10MB/s output processing
- 100,000 sequences in DB without degradation

4. Input Sanitization

   - Prompt injection detection
   - Control character stripping

5. Audit Logging
   - All commands logged
   - All security events tracked
   - Immutable audit trail
   - Queryable with audit_query.py

6. Output Validation
   - Buffer overflow protection
   - Size limits
   - Encoding validation

8.2 Error Handling Strategy
---------------------------

Failure Modes:
1. Tool not found → Log error, skip step, continue
2. Tool crash → Log exit code, save partial output, continue or abort
3. Timeout → Terminate process, log, retry or abort
4. Buffer overflow → Terminate, log, abort
5. Security violation → Block, log, abort
6. Template match failure → Log warning, use fallback, continue

Recovery Mechanisms:
- Automatic retry with exponential backoff
- Checkpoint/resume for long sequences
- Graceful degradation (continue with fewer tools)
- Rollback to last good state
